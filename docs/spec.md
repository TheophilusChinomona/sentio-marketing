# Sentio CRM first version

Approved direction: host a customised Frappe CRM for clients, offer corresponding source under AGPL, keep one site/database per client, and extend with a separate marketing app. Pilot: thuto-tutorials. No live deployment, mailbox connection, messages or paid research in this implementation.

The fork adds Zoho/custom IMAP+SMTP creation and editing to the existing email settings, preserving existing providers. Hostnames/ports/encryption are validated on the server before network access; account create/write permission is checked first. Custom servers use blank Frappe service rather than an unsupported provider enum. Editing can leave a saved password unchanged. Zoho server values are explicit editable presets, not guesses about a mailbox's region.

The app adds site-scoped settings, researched prospects, immutable field evidence, draft email records and suppression records. Import accepts the reviewed account/contact schema, verifies site client and run ID, retains original IDs, dates, holds, unknowns and source evidence, and never grants outreach approval. Generic aliases do not become invented people. A record links to a CRM Organization; a reviewed named record can be promoted to a CRM Lead. The app exposes an authenticated, permission-checked import API and a local CSV-to-JSON preparation CLI; no background provider spending occurs.

Outreach review is separate from mailbox verification. Sales users can review research and prepare drafts; designated managers approve eligibility against recorded evidence. Only valid, supported named contacts with positive approval and no hold/exclusion/suppression are eligible for the initial guarded CRM path. Changing reviewed attributes resets approval. Incoming replies stop follow-up state. Explicit opt-out records suppress matching addresses. CRM-linked outgoing Communication inserts and Email Queue validation recheck eligibility; this is not a claim to control unrelated applications, direct SMTP, or messages already delivered. Default outreach is disabled until the client configures settings. No automatic sequence scheduler is included.

AGPL source information and a maintained-fork changelog accompany a deterministic source export helper. Build files include both the fork and custom app, preserving the existing deployment service/volume names; no code or tenant credentials enter public images or repositories. Unit tests exercise actual policy, import and mailbox boundaries; Frappe integration tests are provided for a real Bench site. Without a local Docker/Bench runtime, database/browser integration is explicitly unverified.
